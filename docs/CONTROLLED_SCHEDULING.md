# 智能可控调度：配置与运行说明

本实现默认保留 legacy。新增迁移 `257_explicit_account_scheduling.sql` 创建调度策略、人工控制、attempt 和会话排空表；不改已有账号 priority 的方向，也不把 load_factor 换算成流量比例。

## 使用入口

- 管理页面 `/admin/scheduling` 按分组、模型保存策略和首字请求档；账号页提供调度控制入口。
- `traffic_weight` 是普通首次派发的目标权重，数字较小的 priority 优先。权重 0 不参与自动业务、重试或探测。
- SWRR、顺序填充和指定账号是独立模式。指定账号默认不允许 fallback；真实硬限制、授权与协议 owner 始终先检查。
- 不配置首字门槛时，只观测首字；真实认证、额度、明确故障等保护仍执行。不要把文档或测试里的示例秒数批量复制到所有模型。
- 查看目标份额、实际普通首次份额和 retry/probe/pin/owner/fallback 例外流量。目标 7:3 不表示 token、账单或最终成功回答 7:3。

管理接口均位于 `/api/v1/admin`，沿用现有管理员鉴权：

| 方法 | 相对路径 | 用途 |
|---|---|---|
| GET / PUT | `/scheduling/policies` | 按 group_id、model 读取或保存策略；保存携带 expected_version |
| POST | `/scheduling/explain` | 只读解释；不调用上游或消耗 SWRR、容量、探测额度 |
| GET | `/scheduling/stats` | 指定分组、模型、时间段的实际派发统计 |
| GET | `/scheduling/requests/:request_id/attempts` | 请求完整 attempt 链及计时、终止原因 |
| GET / POST | `/accounts/:id/scheduling-control` | 读取或操作逻辑账号／凭据族控制状态；写入携带 expected_epoch |

响应头 `X-Scheduling-Request-Id` 可用于查询尝试链。Explain 是当前只读快照，不是预约，也不代替真实请求的用户鉴权、计费、会话 owner 或最终派发准入；并发状态变化后实际结果可以变化。

## 首字与重试

H、R、T、D、M 在 API 中使用毫秒，页面使用秒并转换。配置须满足 `0 < R < H < T <= D` 和 `0 < M <= T`。模型、思考强度、上下文档与协议分别保留健康样本；不可靠上下文使用 unknown，不猜 token 数。

首语义包含正文、推理和有效工具调用。响应头、角色占位、心跳与空事件不算；首正文另记。原生 Gemini / Messages 思考档标签、预算档和别名详见 `backend/internal/scheduling/README.md`。非流式完成时间不冒充 TTFT。

默认整个逻辑请求最多 3 次实际尝试、同层 2 次、同账号 1 次；首次首字超时后最多再派发 1 次。所有适配器共用账本与入站 deadline，已提交语义、不可安全重放或强 owner 不允许迁移时停止。OAuth 控制面刷新可执行，同账号再次生成不绕过账本。

只有一个确实可用、符合后续次数和共享重试额度的后备才预留 M 加切换余量。响应头到达不能延长已经确定的单次期限，也不能收回后备预留。重试退避与等待消耗同一个 D；D 不是已开始回答的整体生成时限。

token 速度不参与选路、健康、恢复、兜底或降级。没有健康备选时，公开的 bounded_best_effort 分支仍遵守暂停、零权重、硬限制和探测准入；它不宣称低性能账号已恢复。

## 暂停与故障处理

- 默认平滑暂停停止新增工作，已获准的请求在原账号完成。暂停生效以 PostgreSQL 准入事务顺序为界，不承诺按钮返回后物理网络上绝无旧请求字节。
- 有界会话排空只允许暂停前登记会话，在截止时间和追加轮次内继续；强制停止尽力取消，可能发生用户可见中断。
- 默认超过 5 分钟仅告警。未知远端状态显示 DRAIN_UNCERTAIN，仍占真实容量，不能为了清空页面数字直接释放。
- 默认操作逻辑账号；凭据族范围需显式选择。恢复只解除人工控制，不解除真实配额、限流、IQ 或健康禁止。
- PostgreSQL 不可用时不接新派发；Redis 不可用时精准模式明确失败。已有流不因控制服务故障被复制或跨账号拼接。
- 普通暂停由 PostgreSQL 准入门和 outbox 传播生效，不依赖 Redis 同步通知，也不承诺同步返回传播告警。强制停止已写入 PostgreSQL 后，若 Redis 取消通知失败，返回 notification_warning；持久取消标记与最终准入门仍有效，其他节点依持久状态继续处理。
- usage 成功持久化才确认同一 attempt 的结算。崩溃、未知状态或未完成财务结算不能被当作成功清零。

## 灰度与回退

上线前备份数据库，并按正常迁移流程应用新增表；所有承接同池请求的网关节点应运行支持权威准入的版本。仅在测试分组确认权重、并发和请求档后启用 `policy.enabled`，再逐组启用。本文和本次代码交付均不自动更改生产流量。

功能回退使用 CAS 保存 `policy.enabled=false`，保留控制状态、owner、在途票据和排空保护。不要通过删除调度表或直接换回不识别准入门的旧服务来模拟安全回退。交付的 `ROLLBACK.sh` 只针对明确指定的离线源码副本，用于验证恢复原始字节；它不是在线数据库降级脚本。

观察每个模型的预算内成功率、整体首字 P50/P95、首正文等待、响应完整率、重试挽救率、调用放大、分流偏差与暂停中断；失败和截断也必须计入观察。已执行和未执行的验证边界见 `CONTROLLED_SCHEDULING_ACCEPTANCE.md`，不能把局部回归或仿真当成 79 项完整生产验收。

## 可用性恢复与延迟证据

完整成功终态和真实首语义延迟分开判定，仍使用一套健康状态机。UNKNOWN / HALF_OPEN 获得 3 个合格完整终态进入 RECOVERING；RECOVERING 各阶段至少持续 30 秒且再取得 3 个合格终态，按 10%、30%、100% 推进。UNKNOWN、HALF_OPEN 和 RECOVERING 期间实际账号探测并发上限仍为 1，达到 HEALTHY 后才恢复正常容量。

- 可用性恢复允许原生非流式的完整成功。HTTP 200、首 chunk、心跳、本地取消、截断均不代表成功；HTTP 错误终态不增加成功计数。
- 120 秒 / 最近 20 个样本用于短期错误及延迟判断，不再清空低频或长回答已完成的恢复资格。健康记录整体 24 小时过期仍会重新冷启动。
- 由慢首语义引起的恢复要求记为 latency，跨 OPEN / HALF_OPEN 保留。非流式成功没有 TTFT，不推进快速恢复、不填 0，也不抹去已有快速证据。
- 健康配置修订、稳定上游身份、Redis Generation 和 StageRevision 分开。真实身份或健康语义变化隔离旧证据；普通 OAuth token 刷新保持身份；缺少稳定身份的 API Key 使用不可逆摘要区分更换。
- 终态观察携带准入时冻结的身份与阶段，不能在完成时重新获取当前阶段冒充旧请求证据。快照与去重凭据同属一个 Redis hash；最多保留 4096 条凭据，达到边界后原子更换 Generation 并保留已形成的状态，旧代在途反馈保守忽略。整 key 淘汰不能复活旧终态。

## 显式故障域与核实入口

账号可以分别声明 quota_pool_id 和 availability_pool_id。默认不声明，不因相同 URL、代理或网站合并。只在结构化上游证据明确匹配已声明池时扩大故障范围；未知 429 留在该账号及实际映射模型，普通 503 不自动封锁整站。认证、配额、模型能力与可用性失败分开反馈，但所有重试继续使用原来同一份次数和时间预算。

共享域恢复只允许一个已准入探测。Redis 租约用于竞争，PostgreSQL 既有 attempt 上的域占位才是远端在途的权威事实；租约过期、Redis 丢失、进程重启和管理员 resume 均不能释放 UNKNOWN 占位。域门只保存原因、期限、版本和占位，不再建立一套域级延迟或恢复阶段状态机。

账号控制弹窗提供故障域声明与版本检查。请求尝试链提供 UNKNOWN 详情和核实终态入口，提交必须包含当前版本、核实来源、证据引用、核实时间与真实结果；仅时间过去或本地取消不构成证据。核实结算保留审计并幂等释放一次容量，费用是否待结算独立保留。

## 配置继承与元数据边界

profile 健康语义变化、显式 reset 由 PostgreSQL 分配新健康修订。只调整总预算 D、最小后备 M、权重和优先级不重置健康资格。改回旧参数也不会复用已废弃修订。分组恢复继承保留 CAS 版本墓碑，防止删除后版本回到初值；已有请求继续持有自己的冻结策略。

相同优先匹配级别的重叠 profile 在保存时拒绝，旧配置冲突在 Explain 明确显示。入站和实际出站元数据使用有界内存扫描，大正文后面的 model / stream 字段不再受 256 KiB 前缀截断影响；未知上下文长度仍为 unknown，不凭字符数猜 token。D 约束首语义之前的数据库、Redis 准备和等待，已经输出的长流继续由实际上游和客户端生命周期控制。

## 本轮新增接口

所有路径仍在 /api/v1/admin 管理员鉴权下：

| 方法 | 路径 | 作用 |
|---|---|---|
| DELETE | /scheduling/policies | 携带 expected_version 恢复分组继承，保留版本墓碑 |
| GET / PUT | /accounts/:id/failure-domains | 查看门与声明两个故障池，写入要求 expected_version |
| POST | /accounts/:id/failure-domains/recovery | 带域版本、门版本与核实证据申请单探测恢复 |
| GET / POST | /scheduling/attempts/:ticket_id/resolution | 查看或核实 UNKNOWN，要求版本与终态证据 |

保存策略时可提交 reset_health_profiles 名称列表请求重新建立健康证据；服务端分配修订，客户端不能指定旧修订回灌。门恢复和 UNKNOWN 核实会留审计，不通过切换 enabled 或恢复人工控制绕过。
