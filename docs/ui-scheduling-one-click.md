# 一键账号调度界面

本轮是现有后台的操作精简，保留 Vue、Tailwind、系统字体、主题与表格样式。设计按 impeccable 的 Operate 模式处理；taste 不用于替换后台设计系统。已有 GSAP 保存反馈继续使用作用域清理及 prefers-reduced-motion，不增加入场编排。

## 管理员操作

- 账号管理保留原来的“调度”开关。单击即提交该账号的 schedulable，不打开暂停/恢复或影响范围弹窗。关闭停止新请求，已开始的请求继续完成；开启重新按当前调度规则参与流量。
- 每个账号有独立提交锁。同一账号的连续点击、单账号与批量调度操作不能同时覆盖。请求失败时保留最后确认状态，显示错误并允许重试。
- 账号列表的普通刷新和自动刷新都保护提交中的开关；晚到的旧响应不能恢复旧值。后续正常刷新仍能读取其他管理员的更新。
- 可控智能调度只保留策略分组、账号顺序与分配比例、等待与自动换号。优先级和权重在本组保存，所有模型共用；保存仍有版本冲突保护和未保存草稿保护。
- 账号创建、编辑和批量编辑不添加凭据家族、共用额度、服务域、故障诊断或故障排查设置。
- Sub2API 原版模式仍保留自己的设置与调度权值显示；切换模式的入口和版本校验不变。

## 删除的前端代码

删除暂停/恢复、故障域编辑、故障恢复、未知请求人工核对、尝试链与旧分流诊断组件；同时删除相应 API 客户端、无使用者的逐模型策略工具、类型、文案和旧组件测试。必要的错误反馈、加载状态、账号当前开关状态不属于故障诊断，仍然保留。

## 验证范围

组件回归覆盖一键开关、重复点击、不同账号并行提交、失败重试、单个/批量互斥、旧列表晚到、两种模式、分组隔离、版本冲突、完整分组保存与分页。浏览器使用最终生产构建和本地合成 API，核对键盘、桌面/手机、深浅主题及减弱动效。

完整命令、失败记录、报告与截图保存在候选目录的 evidence/frontend/ 与 browser-evidence/。这些前端检查不代表已验证真实上游的首字延迟或生产负载。
